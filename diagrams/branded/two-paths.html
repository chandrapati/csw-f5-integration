Two paths. They fail independently.

Seeing the real client and naming the virtual server are different integrations. Either one can be healthy while the other is dark.

Path 2 · do this first

F5 connector — see the real client

  • The BIG-IP pushes IPFIX to the F5 connector on an Ingest appliance.
  • Default listen port is UDP 4739.
  • Both halves are correlated and annotated. They are not merged into one record.
  • The generic NetFlow connector collects the same export and leaves the client behind the SNAT address.
Path 1 · after the picture is right

External Orchestrator — name the VIP

  • Secure Workload pulls virtual servers over iControl REST.
  • Each single-address VIP becomes service_name.
  • Enforcement, when the three gates are open, pushes security rules back over the same API.
  • SaaS, or a BIG-IP CSW cannot route to, uses a Secure Connector tunnel.
Order that keeps a proof of value calm: connector first, orchestrator second. See the traffic, confirm it matches the estate, then name the VIPs and write policy.
